# Property gallery correction — 2026-09-14

User reported reversed arrows, zoom on rapid taps, and unreachable thumbnail-strip items. Scope: public Mavo catalog, shared gallery across homepage/search/neighborhood pages. No property data, forms, recipients or permissions changed.

Root causes: RTL arrow glyph mirroring and LTR-only keyboard order; controls use default touch behavior; the thumbnail flex row has neither a constrained inline size nor scrolling and is clipped by the gallery parent.

Changes: RTL previous/right and next/left placement with explicit non-mirrored glyphs, matching keyboard direction; `touch-action: manipulation` and cancel native dblclick on controls without cancelling either click or disabling pinch zoom; bounded horizontal strip, nonshrinking thumbnails, wheel support, native thumbnail buttons with labels and scroll-to-selection. Shared asset versions bumped on consuming HTML pages.

Verification:
- Regression reproduced before change: ArrowLeft in Hebrew selected last rather than second image.
- Node tests: 27/27 pass, including Hebrew/English direction and repeated navigation wraparound.
- Local IAB at 320x740, property 40: strip clientWidth241/scrollWidth288/overflowauto; selecting final thumbnail with keyboard scrolls to -45 and selects image5.
- RTL arrows: previous at x268 pointing right; next at x8 pointing left; controls touch-action manipulation.
- Real browser dblclick from image5 selected image2 (two advances), viewport scale remained1, overlay positionfixed; ArrowLeft then selected image3.
- Physical iOS/Android touch gesture was not tested. Desktop-engine dblclick + computed touch behavior are verified, not a substitute for hardware Safari gesture QA.
- Existing isolated worktree reused; pre-change Git bundle retained privately. No unrelated source changes were present.
